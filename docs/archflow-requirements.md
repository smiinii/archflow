# Archflow 합의된 요구사항

최종 갱신: 2026-10-21. 사용자 저장소: https://github.com/smiinii/archflow

이 문서는 이 대화에서 합의한 제품 요구사항의 기준이다. 구현 요청을 받으면 먼저 이 파일과 `ai-interview-prompt.txt`, `storage-plan.md`를 읽는다. 초기 디자인 미리보기를 기준으로 이 저장소에 실제 앱을 구현했다. 배포 상태와 검증 범위는 아래 구현 상태를 따른다. 새 기능을 만들면서 이전에 승인된 기능을 생략하지 않는다. 범위 변경은 사용자와 확인한다.

## 제품과 사용 흐름

- 이해하기: 이미 개발·운영 중인 서비스의 전체 아키텍처와 API별 요청 흐름을 이해한다.
- 설계하기: 요구사항을 정리하고 새로운 구조를 설계한다.
- 개선하기: 설정한 수치와 목표를 비교해 문제 후보와 대가를 파악한다.
- 한 프로젝트의 전체 아키텍처와 여러 API 흐름은 같은 그래프를 공유한다. 전체 보기에서 구성·배포 관계까지 표현하고, API 보기에서는 해당 요청 경로를 강조한다.
- 프로젝트를 여러 개 만들고 폴더/디렉터리로 정리한다. 프로젝트별 이름·설계·요청·설정·인터뷰 결과를 독립적으로 저장한다.

## 디자인·편집

- 밝은 Figma/Sketch 계열 편집기. 중립적인 패널과 캔버스, 가벼운 그림자가 있는 구성요소. 장식적인 AI 대시보드 스타일은 피한다.
- 왼쪽 프로젝트/레이어/구성요소, 가운데 캔버스, 오른쪽 선택 속성·진단, 간결한 도구 모음.
- 기술/공급자 실제 아이콘을 사용한다. 동일 기술의 구성요소를 여러 개 추가·복제하고 `회원 API`, `주문 DB` 같은 역할 이름을 각각 붙인다. 기술명과 역할명은 구분한다.
- 구성요소 및 그룹을 마우스로 이동하고 크기를 조절한다. 가로·세로·모서리 조절점을 제공한다.
- 그룹은 선택하지 않으면 얇은 점선, 선택하면 실선과 조절점. 점선 또는 제목을 클릭해 선택한다.
- 그룹 이동 시 내부 구성요소와 연결선도 함께 이동한다. 영역 드래그/Shift 클릭/전체 선택으로 여러 요소를 함께 이동한다. 손 도구/Space 드래그로 화면 이동을 지원한다.
- 중심·변 정렬, 좌우 대칭, 같은 간격 안내선과 자동 스냅. 자석 버튼으로 끄고 Alt로 임시 해제한다.
- 구성요소/연결 선택 후 Delete 또는 Backspace로 삭제한다. 이름·숫자·텍스트 편집 중의 삭제 키는 입력만 수정한다. 노드 삭제 시 관련 연결과 요청 참조도 정리하고 실행 취소를 제공한다.
- 모바일에서 주요 조작/설정/보기는 유지하고 가로 넘침을 막는다. 섬세한 마우스 편집은 데스크톱을 우선한다.

## 연결·모션

- 동기: 실선. 비동기: 점선. 단순 배포/구성 관계는 별도 라벨·스타일로 구별한다.
- 구성요소를 선택하면 동기 연결/비동기 연결 두 동작을 제공한다. 출발점에서 여러 대상을 연속 선택해 1:N 연결할 수 있다. 같은 대상으로 여러 출발점에서 연결하는 N:1/N:M도 허용한다.
- 연결마다 타입과 설명, 포함되는 API 흐름을 저장한다. 연결 선택 후 타입 변경과 삭제를 지원한다.
- 연결선을 따라 요청 점이 이동한다. 모션 스위치로 켜고 끄며 꺼도 계산은 계속 갱신한다. 선택을 기억하고 시스템의 움직임 줄이기 설정을 고려한다.
- 동기/비동기는 연결의 속성이다. 같은 컴포넌트를 무조건 동기 또는 비동기로 취급하지 않는다. 비동기 경계 뒤의 처리 실패를 즉시 응답 실패와 구분한다.

## 구성요소 라이브러리

- AWS 서비스·리소스 아이콘을 배포본 전체 기준으로 수록하고 검색/분류/페이지 이동을 제공한다. 현재 미리보기의 고정 소스는 AWS Labs v23.1 배포본 872종이다. AWS의 현재 모든 제품을 빠짐없이 지원한다고 과장하지 않는다.
- Docker, Kubernetes, DB/캐시, 메시징, 프록시, 백엔드 런타임, 검색, 인증, 배포, 관측, 네트워크, 운영 도구 등을 포함한다. 현재 백엔드·인프라 추가 목록은 75종이다.
- LMS에서 확인한 로드 밸런서, API 서버, SQL DB, CDN, Blob Store, 인코더와 기본 역할을 포함한다.
- 목록에 없으면 사용자 정의 구성요소를 추가할 수 있다. 성능·가용성 기본값을 공급자의 보장값으로 표시하지 않는다.
- Docker/배포 도구/경계 같은 구조적 요소는 요청 처리 용량·직렬 곱에 자동 포함하지 않는다.

## 수치·진단

- 요청별 RPS, 캐시 적중률, 응답 시간 목표, 가용성 목표. 구성요소별 평균 처리 시간, 처리 시간 목표, 실제 병렬 처리 수, 대수, 가용성, 연결 지연, 요구 호출 부하/횟수를 편집한다.
- 수치를 바꾸면 부하·용량 비율과 기본 지연, 가용성 비교를 즉시 갱신한다. ms/초 단위와 평균/p95/p99, 현재 측정/가정/목표를 구분한다.
- 한계를 넘는 곳을 빨간색과 텍스트로 표시하고 클릭 시 원인·비교 수치·영향·검증 방법·변경 예시를 보여 준다.
- 용량은 병렬 슬롯·대수에 비례하는 단순 모델임을 밝힌다. 앞단 포화 제한, DB 공유 한계, 실제 대기·p99를 정확히 예측한다고 하지 않는다.
- 직렬 가용성은 응답 완료에 필수인 동기 의존성에 대해 독립 고장 가정으로 계산한다. 비동기 뒤의 최종 완료 신뢰성은 별도다. 공통 장애·우회/중복 구조·SLA 보장과 구분한다.
- 기본 지연은 명시된 경로의 처리·연결 지연에 대한 가정이다. 병렬 분기를 무조건 합산하거나 전송/인코딩/대기 시간을 포함했다고 하지 않는다.
- 속성의 ‘수치의 의미’는 처리 용량·가용성·연결 지연·직렬 경로·요구 RPS를 짧게 설명한다.

## 승인된 AI 인터뷰와 사용자 비용

- `ai-interview-prompt.txt`의 프롬프트를 사용한다. 사용자가 승인했다.
- AI에게 Archflow의 역할을 먼저 알려 주고, 사용자의 목적·핵심 기능·실제 구현/배포·데이터·장애·수치/목표를 적응형 인터뷰로 확인한다. 질문은 한 번에 2~3개.
- 사실/추정/미확인/실측/목표와 현재 구조/개선안을 구분한다. 모르는 수치를 채워 넣지 않는다. 예시 캔버스는 실제 서비스 근거가 아니다.
- 인터뷰 완료 확인 뒤 현재 구조 설명, 구성요소·연결·그룹 명세, 문제 후보와 근거, 우선 작업 최대 3개를 제공한다.
- 사용자가 이용하는 외부 AI에서 실행한다. 서비스 운영자 모델 API 키로 자동 호출하는 기능을 기본값으로 넣지 않는다.
- 먼저 프롬프트 복사/결과 검토·가져오기를 완성한다. JSON 가져오기는 실제 스키마와 검증·미리보기·되돌리기를 구현한 후 제공한다.
- 이후 MCP/브라우저 제어를 통해 사용자의 AI가 같은 설계 데이터를 읽고 수정할 수 있는 연결을 검토한다. 도구가 없는데 자동 수정했다고 말하지 않는다. 개선안은 별도 버전으로 비교한다.
- 백엔드 코드 분석에는 사용자가 제공/허용한 코드·설정·로그 근거를 사용한다. 서비스 URL만으로 내부 구조를 안다고 하지 않는다.

## 저장·배포와 상태 구분

- 공개 GitHub 저장소에 코드, Vercel에 웹 앱 배포를 예정한다. 프로젝트 데이터는 기본 비공개이며 공개 코드 저장소에 개인 설계를 커밋하지 않는다.
- DB 권장안은 Supabase Postgres + Auth. 사용자→폴더→프로젝트→그래프/요청/버전 구조. 자세한 내용은 `storage-plan.md`.
- 현재 미리보기 저장은 대화/브라우저 범위이며 실제 클라우드 DB·로그인·기기 간 동기화가 구현된 것으로 표시하지 않는다.
- 구현 시 이 문서를 수락 기준 체크리스트로 사용하고 완료/미완료/제약을 사실대로 갱신한다. ‘모든 것을 영구히 기억한다’고 약속하는 대신 이 파일을 다음 작업의 기준으로 읽는다.

## 이번 미리보기 확인 범위

- 전체 구조/API 보기 전환, 폴더·프로젝트 생성, 빈 프로젝트 구성요소 추가, 프로젝트 전환 시 그래프 분리.
- 노드 마우스 가로·세로 확대와 그룹 가로 확대. Delete/Backspace 삭제, 연결 정리, 실행 취소, 입력 필드 삭제 보호.
- 동일 출발점의 복수 비동기 연결, 기존 연결의 타입 변경, 비동기 경계에 따른 즉시 응답 계산 항 수 변경.
- 승인된 인터뷰 프롬프트 표시, 320px·375px에서 가로 넘침 없음.
- 이 확인은 대화용 미리보기 동작에 관한 것이다. 운영 DB·로그인·GitHub 제품 코드·배포 검증은 아직 하지 않았다.

Vercel 운영 환경 변수·GitHub 단일 저장소 연결·로그인 복귀 주소를 설정했고 Ready 상태와 배포된 편집기·로그인 UI를 확인했다. 사용자의 이메일 링크 로그인과 실제 DB 저장·revision 갱신을 확인했고, 사용자가 ‘클라우드 저장됨’ 표시 및 새로고침 후 프로젝트 유지를 확인했다. GitHub main 푸시의 Vercel 자동 재배포도 확인했다. 다른 기기 복원은 별도 검증 항목이다. 기본 메일은 Supabase 팀원 주소만 지원하므로 일반 사용자 이메일 로그인에는 별도 SMTP가 필요하다. 상세 상태는 `deployment.md`를 따른다.
- 저장 방식은 초기 관계형 분할 제안을 단순화해 사용자별 `workspaces` JSONB 스냅샷과 revision을 사용했다. 폴더/프로젝트/API/버전의 원자적 저장을 우선했다. 한도와 추후 프로젝트별 테이블 분리는 README·deployment.md에 적었다.
- 실시간 공동 편집, MCP 직접 제어와 운영 서버 자동 수집은 기존 합의대로 후속 검토 항목이다. 이번 앱은 외부 AI 프롬프트·JSON 교환을 지원한다.

## 편집기 UX 변경 (2026-10-21 추가 승인)

이 절은 이전 문서의 화면 배치·버전·수동 파일 교환 요구보다 우선한다.

- 사용자의 최종 정정에 따라 기본 빈 공간 드래그는 영역 선택, 손 도구 또는 Space 드래그는 화면 이동으로 유지한다. 확대/축소와 구성요소 크기 조절 기능도 유지한다.
- 프로젝트 제목 오른쪽 네모 버튼은 왼쪽 사이드바를 접는다. 접었을 때 상단 왼쪽에 펼치기 버튼을 남긴다. 프로젝트 관리는 별도의 설정 버튼으로 구별한다.

## 전체 캔버스와 페이지 스크롤 (2026-10-21 최종 정정)

- 사이드바를 접은 후 펼치기 버튼은 로고 옆이 아니라 ‘전체 구조’ 버튼 바로 왼쪽에 둔다.
- 속성·진단은 고정된 하단 분할 패널이 아니다. 첫 화면에는 가용 높이를 전부 사용하는 아키텍처가 보이고, 그 다음에 상세 정보가 이어지는 페이지 스크롤 구조다. 이전 절의 크게 보기/고정 패널 설명을 대체한다.
- 요소나 선을 선택하면 아래 상세 내용만 갱신한다. 캔버스 높이와 배율을 바꾸거나 화면을 자동으로 아래로 이동하지 않는다.
- 캔버스 위의 일반 휠은 페이지를 아래로 스크롤한다. 확대·축소 버튼, Ctrl+휠과 핀치는 확대용으로 남긴다. 선택 드래그·손 도구 이동은 유지한다.
- ‘아래에서 속성·진단 보기’와 ‘아키텍처로 돌아가기’는 사용자가 눌렀을 때만 해당 영역으로 이동한다. 상세 내용은 자체 높이를 가지며 내부의 작은 스크롤 영역에 가두지 않는다.
- 처음 전체 맞춤과 수동 전체 보기에 도구막대 여백을 적용해 마지막 구성요소가 가려지지 않게 한다.
- 브라우저 검증: 요소 선택 전후 캔버스 높이·viewport 값·페이지 위치가 동일함을 확인했고, 일반 휠로 상세 정보까지 이동할 때 확대 비율이 변하지 않는 것을 확인했다. 사이드바 복원 버튼이 전체 구조 왼쪽에 있는 것과 375px에서도 상세 영역이 첫 화면 아래에 있고 가로 넘침이 없는 것을 확인했다.

## 프로젝트 삭제와 드래그 정리 (2026-10-21 추가 요청)

- 사이드바 및 프로젝트 관리 목록에서 프로젝트 행을 끌어 폴더 간 이동하거나, 다른 프로젝트 위/아래에 놓아 같은 폴더 내 순서를 바꾼다. ‘폴더 밖으로 이동’ 영역에 놓으면 작업공간 최상위로 옮긴다. 폴더 자체의 드래그 이동은 이번 범위가 아니다.
- 프로젝트 행의 휴지통 버튼 또는 프로젝트 관리의 ‘현재 프로젝트 삭제’로 삭제 확인 창을 연다. 이름과 삭제 범위를 확인하고 취소 또는 삭제를 선택한다.
- 현재 프로젝트를 삭제하면 남아 있는 프로젝트를 연다. 마지막 프로젝트를 삭제할 때는 저장 형식의 최소 1개 조건에 맞춰 빈 ‘새 프로젝트’를 만든다.
- 마지막으로 삭제한 프로젝트는 새로고침 전까지 알림의 ‘삭제 취소’로 복구할 수 있다. 별도 영구 휴지통은 아니다. 취소할 때 삭제 직전의 그래프·요청·인터뷰·과거 버전 데이터를 복원하며, 삭제 후 빈 프로젝트에 새로 작성한 내용은 지우지 않는다. 계정이 바뀌면 삭제 취소 상태를 비운다.
- 이동·순서는 기존 자동 저장에 포함한다. 드래그가 어려운 환경에서는 프로젝트 관리의 저장 폴더 선택을 계속 사용할 수 있다.
- 검증: 프로젝트 정리 관련 7개 테스트를 추가했다. 브라우저의 로컬 검증용 프로젝트로 폴더에 넣기·폴더 밖으로 꺼내기·위아래 순서 변경, 삭제 확인·삭제 취소·새로고침 후 순서 유지를 확인했다. 삭제 버튼은 스크롤바와 겹치지 않도록 여백을 확보했다.

## AI 구조 가져오기·흐름 가독성 (2026-10-21 추가 요청)

사용자가 붙여넣은 ‘AI 구조 가져오기: 디자인 유지와 흐름 가독성 개선’의 P0·P1을 반영했다.

- 가져온 카드와 수동 카드는 같은 catalogId 렌더러를 사용한다. 역할 이름은 두 줄, 긴 설명은 아래 상세에 둔다. 표시 최소 크기 200×148px과 이유를 속성/가져오기에 안내한다. 작은 원본의 저장 크기는 보존하고 표시 크기에만 최소값을 적용한다. 그룹 제목은 내부 여백에 두며 자식 범위 맞춤은 절대 좌표를 유지하고 실행 취소할 수 있다.
- 카드·그룹 제목을 장애물로 보는 직교 경로 탐색과 병렬·역방향 연결의 경로 분산을 추가했다. 설명은 최대 12자로 축약해 배경과 여백을 두고, 카드·다른 설명을 피하는 위치를 찾는다. 필요하면 짧은 보조선으로 설명을 연결한다. 위치가 없으면 억지로 겹치지 않고 선택 상세로 읽는다. 경로를 찾지 못한 연결은 경고하고 카드 내부를 관통해 그리지 않는다.
- 연결 설명 숨김/선택만/전체, 70% 미만에서 설명 숨김, 선택·키보드 포커스의 전체 설명을 제공한다. 동기·비동기·구성 관계는 실선/점선/촘촘한 점선이다. 모션 켜기/끄기는 유지한다.
- 선택 흐름만 보기는 해당 연결의 모든 양 끝·시작/완료 지점과 부모 그룹만 남긴다. 전체 안에서 강조는 나머지 카드와 연결을 흐리게 남긴다. 화면 맞춤은 카드 범위로 계산하고 최소 85%를 유지한다. 큰 흐름은 시작점에서 읽으며 요소 이동/연결 따라가기/손 도구를 사용한다. 전체 윤곽 버튼은 축소 개요다. 흐름 변경은 저장된 좌표를 바꾸지 않으며 숨겨진 이전 선택은 해제한다. 화면 크기 변경은 기존 세계 좌표의 중심과 배율을 유지한다.
- 연결 목적 delivery/dependency를 명시하고 가져오기와 속성에서 검토한다. 참조용 상태 확인·의존 표시는 전달 계산에서 제외되므로, 실제 호출 부하를 계산할 DB 조회까지 일괄 제외하지 않도록 안내한다. 그래프의 순환 모양만으로 실제 순환 호출·독립 장애를 단정하지 않는다. 조건·캐시 미스·상세 설명을 별도 보관한다.
- responseId/completionId로 HTTP 응답과 최종 완료 표시 지점을 나눈다. 이 표시만으로 계산 경계를 추정하지 않고 entryId/requiredIds/동기 도달 경로가 계산 범위다. FCM 수락과 기기 화면 표시도 구분한다.
- 가져오기 미리보기에 역할·기술·아이콘·매핑 상태와 교체 입력을 제공한다. 미지원 ID는 조용히 대체하지 않고 적용을 차단한다. 외부 API였던 FCM/Slack은 전용 디자인으로 명시적으로 교체할 수 있다. FCM·Firebase는 공식 배포 SVG, Slack은 Devicon SVG를 로컬 수록했다. 임의 style/아이콘 URL은 지원하지 않으며 제외 확인을 받는다. 아이콘 로드 실패를 매핑 목록에 표시한다.
- 주요 실제 catalogId와 사용 중인 기술을 인터뷰 프롬프트에 포함하고 전체 카탈로그 복사도 제공한다. 모르는 수치를 null로 둘 필드와, replicas/calls/hitPercent의 필수 기본 숫자 및 unknown 근거를 구분한다. 미확인 처리·대수·가용성, 호출 횟수·RPS·캐시 값으로 관련 결론을 내리지 않는다. 이전 형식의 누락된 호출/RPS/캐시 근거는 기존 설계 가정으로 호환한다.
- 오류는 요소 이름·필드·현재 길이/허용값으로 안내한다. 누르면 JSON 값을 선택하고, 수정 후 재검증할 수 있다. 적용 불가 이유와 남은 오류 수를 버튼 옆에 표시한다.
- 현재 프로젝트와 입력 구조를 비교해 추가/삭제/이동/그룹/크기/이름·기술/연결 종류 차이를 보여준다. 공통 ID의 이름·크기·절대 좌표를 맞춘 비교는 보기만 바꾸며 원본 비교로 전환할 수 있다. 배치 변경은 미리보기/취소 후 적용하고 가져오기에서는 이전 배치로 되돌리기, 편집기에서는 실행 취소를 지원한다.
- 기존의 전체 높이 캔버스와 아래 상세 페이지 스크롤, 프로젝트 삭제/드래그, 사이드바 복원 위치는 유지한다. 새로 고침 후 아이콘 매핑·참조 구분·배치가 기존 저장 방식으로 보존된다. 새 선택 필드는 기존 JSONB 저장 형식과 호환되므로 DB 권한·마이그레이션 변경은 없다.

- 47개 자동 테스트와 타입 검사·프로덕션 빌드를 통과했다. 23개/26개 연결의 카드 관통·라벨 충돌, 병렬/역방향, 그룹 절대 좌표, 흐름 필터, 비교, 필드 오류 위치, 미확인 수치, 서버 시작점의 지연 포함을 검사한다.
